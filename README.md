# Рик и Морти — персонажи

Учебное приложение для ДЗ №2 по веб-разработке (Vite + Vanilla JavaScript). Страница ходит в публичный API через `fetch`, показывает персонажей карточками, умеет искать по имени и фильтровать по статусу.

**Сайт:** https://fsl-tikaani.github.io/homework-web-2/

**Репозиторий:** https://github.com/FSL-Tikaani/homework-web-2

## API

[Rick and Morty API](https://rickandmortyapi.com/) — без ключа, по HTTPS, с включённым CORS, поэтому запросы работают прямо из браузера. Он входит в список [public-apis](https://github.com/public-apis/public-apis) (раздел Games & Comics).

Используем один запрос:

```
GET https://rickandmortyapi.com/api/character/?name=rick&status=alive&page=1
```

Документация: https://rickandmortyapi.com/documentation/#character

## Что умеет приложение

- Поиск по имени и выбор статуса (живой / мёртвый / неизвестно).
- Кнопка «Обновить» повторяет текущий запрос.
- Кнопка «Тест ошибки» отправляет запрос на несуществующий адрес API (сервер отвечает HTTP 404), чтобы показать экран ошибки; «Повторить попытку» после этого загружает данные как обычно.
- Пагинация «Назад» / «Вперёд».
- Состояния интерфейса:
  - **Загрузка…** — пока идёт запрос, кнопки заблокированы;
  - **Ничего не найдено** — если подходящих персонажей нет (API отвечает на это статусом 404, и мы обрабатываем его отдельно);
  - **Ошибка** — понятное сообщение и кнопка «Повторить попытку».
- `response.ok` проверяется в `src/api.js`: HTTP 404 и 500 сами по себе не отклоняют `fetch`.
- Устаревшие запросы отменяются через `AbortController`, чтобы поздний ответ не перезаписал свежий.

## Запуск

Нужен Node.js 20.19+ (или 22+) и npm.

```bash
npm install        # установить зависимости
npm run dev        # сервер разработки, откроется на http://localhost:5173
```

## Сборка

```bash
npm run build      # готовый сайт появится в папке dist/
npm run preview    # посмотреть сборку локально
```

Публикуется содержимое `dist/`. Папку `node_modules/` на хостинг не копируем.

## Публикация на GitHub Pages

В репозитории уже есть workflow `.github/workflows/deploy.yml`. Он собирает проект и выкладывает `dist/` при каждом пуше в `main`.

1. Создайте репозиторий на GitHub и запушьте в ветку `main`.
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Дождитесь зелёной галочки во вкладке **Actions**. Адрес сайта появится в Settings → Pages.

## Структура

```
index.html        разметка и контейнеры для состояний
src/api.js        getCharacters(): fetch, проверка response.ok, разбор JSON
src/main.js       состояния, события, отрисовка карточек
src/style.css     стили
vite.config.js    base: "./" — сайт работает в любой подпапке
```
